# 一方小海 · Windows 桌面景观

在原 Three.js 0.180.0 项目上增量接入 Tauri 2。轮船、海洋截面、海豚、多边形海鸥和四层极光沿用原场景；网页与桌宠使用同一前端和一个渲染器。

当前开发版本将船只档案、九款整船皮肤、饰品和叙事日志统一放进海洋旁的常驻航海手账，使用 `npm run preview:gm` 保留 GM 工具预览。本次桌面交付为 `outputs/Tiny-Tides-GM-2026-09-21-smooth-audio.exe`，旧 EXE 与安装包单独保留；源码构建与交付包独立维护。实测与未测项见 [TEST_RESULTS.md](TEST_RESULTS.md)。启动新版前先从托盘退出旧版；应用保留单实例限制，重复启动会转到旧实例。

## 项目结构与修改入口

当前游戏只有一份可编辑源码：项目根目录的 `main.js`、`template.html` 和各 `.mjs` 模块。Codex 后续修改游戏功能也只修改这些文件，不直接修改生成的 HTML 或 EXE。

- `history/html/`：过去的独立 HTML 快照，纳入 Git，只用于回看。
- `preview/index.html`：由当前源码生成的未打包预览，纳入 Git，便于检查每次修改后的网页效果。
- `desktop-dist/index.html`：由同一份源码临时生成的桌面打包输入；由构建命令维护，不纳入 Git。
- `src-tauri/`：透明窗口、托盘和桌面系统功能。
- `src-tauri/target/release/`：最终 EXE 和安装包构建产物，不纳入 Git。

## 测试未打包效果

开发预览：

```powershell
npm ci
npm run preview
```

打开 http://127.0.0.1:4173/ 。`npm run preview` 会先根据当前源码重建 `preview/index.html`，再启动本地预览；修改源码后重新执行该命令并刷新。环境音默认开启，使用原有低音量自然录音；若浏览器限制自动播放，首次点击页面或按键时恢复播放，也可点击“听海”。点击“静音”后本次运行不再自动打开；桌面已有明确保存的静音设置继续保留。

不要直接编辑 `preview/index.html`。它是可查看、可提交的生成快照，下次构建会覆盖。双击项目根目录 `template.html` 会自动打开当前已构建的 `preview/index.html`，不再停在加载提示；修改源码后仍需执行 `npm run build:gm` 更新快照。日常开发推荐上面的本地预览地址；file:// 与 http:// 的浏览器存档互相独立。

## Windows 开发与打包

依赖：Windows 10/11、Node.js LTS、Rust MSVC stable、Visual Studio C++ 桌面开发工作负载（MSVC x64/x86 和 Windows SDK）、WebView2。仅安装 Visual Studio 编辑器并不足够。[Tauri 官方前置要求](https://v2.tauri.app/start/prerequisites/)。

本机已安装 Rust stable 到 C:/Users/ww/.cargo/bin，未修改系统 PATH；运行前可将该目录加入当前终端 PATH。用户已通过 Visual Studio Installer 安装 C++ 工作负载与 Windows SDK，此前 link.exe 缺失的构建阻塞已解除。

```powershell
npm ci
npm test
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
npm run desktop:dev
npm run desktop:build
```

应用构建产物位于 src-tauri/target/release/tiny-tides-pet.exe，NSIS 安装包位于 src-tauri/target/release/bundle/nsis/。交付目录同时提供改名后的 EXE 与安装包。

`npm run desktop:dev` 和 `npm run desktop:build` 会先生成 `desktop-dist/index.html`，不会读取或修改 `preview/index.html`。应用脚本与音频嵌入 HTML；模型和纹理由本地代码创建，没有在线资源请求。安装包包含离线 WebView2 安装器，因此首次**构建**仍需下载构建依赖及 WebView2 安装器；最终安装和运行不依赖 CDN。直接运行 EXE 需要机器已安装 WebView2，本机已具备。NSIS 安装与卸载流程尚未实测。应用未配置签名证书。

## 桌宠操作

默认 560×540 逻辑像素、透明、无边框、无标题栏、无系统阴影、置顶、不抢焦点。展示状态通常鼠标穿透；当前开发版每 100 ms 检查光标是否命中真实船体或可见的未读小册，仅命中时接收点击，悬停不抢焦点。先建立托盘再显示窗口，避免无法恢复交互。新增原生命中交互仍需 Windows 实机操作验收。

右键托盘可显示/隐藏、编辑/锁定、切换置顶、暂停/继续、选择 30/20 FPS、开关环境音、重置位置和视角、保存性能诊断、退出。再次启动应用会通过单实例机制打开原窗口的编辑模式。

编辑模式使用“移动窗口”专用按钮拖动窗口；在海面区域拖动仅控制 OrbitControls。结束后点“锁定展示”或按 Escape。观察角度、波幅、位置、置顶和帧率保存在 %APPDATA%/com.tinytides.desktop/settings.json。位置使用物理坐标，支持负坐标显示器；托盘重置回主屏工作区。显示器或缩放变化会触发位置恢复，窗口大于工作区时等比缩小。退出前会保存状态。

隐藏、最小化或暂停时停止绘制和世界时间；恢复不补算历史帧。单纯失去焦点不暂停桌宠。网页预览在标签页隐藏时暂停。

船灯跟随昼夜平滑变化：白天（包括雨天）熄灭，黄昏逐渐点亮，夜间保留柔和暖光，晨光渐灭。亮度和窗口自发光参数位于 `boat-model.mjs` 的 `updateLighting`；点光源贴合实际桅灯，拆除旗杆时关闭，不再在船头生成强亮斑。

## 航海手账 · 当前交互

点击海洋右下外侧的 **薄荷绿海洋插画手账**。没有新日志时书也一直存在；新见闻只增加浅蓝灰书签，线索书签更长、偏蓝绿。点击小船不再打开设置或改变相机。

- 第 1–2 页：原位改名、首次启航日期、海里说明、当前航行意图、见闻数，以及可拖动／方向键旋转的船只记录模型。首次启航日期在旧存档里未知时如实显示“日期未记下”。
- 第 3–4 页：九款整船皮肤全部免费直接切换；随船物件按七个位置和航行徽章选择。未获得物件隐藏，GM 构建仍可试装。不恢复颜色购买。
- 第 5 页起：连续航海日志。黄纸条跳到“我的船”，蓝纸条跳到最新日志的开头；一次平顺翻动到目标跨页。右下纸角前进、左下纸角返回；也支持方向键与 PageUp/PageDown。

点击铅笔原位改名，Enter／点击空白保存，Escape 取消；同步手账入口的无障碍名称、记录图标题和海上船铭牌，旧日志船名不改。点击海里展开纸张便利贴。外观和装备变动写成去重的页边批注，有对应见闻时关联来源页，不生成大量新日志。

入口与展开书复用同一个 DOM。开书约 1.05 秒、普通翻页约 0.62 秒、章节跳转约 0.7 秒、合书 0.9 秒；点击书外或 Escape 合上并回到当前窗口布局中的原处。书写／绘画／翻页中请求关闭会等待完成。支持系统减少动画偏好。海里的船始终为 75%，不移动原相机，阅读期间继续航行、推进天气并累计有效海里；手动暂停、隐藏和最小化规则仍有效。

实现：`journal/journal-book.mjs` 管理七个交互状态，`ship-pages.mjs` 复用已有外观服务，`pages.mjs` 用实际 DOM 高度分页，`writing.mjs` 负责铅笔和声音。纸页预览共用海上船几何、材质和铭牌纹理；一个 WebGL Renderer，以固定 320×320 离屏目标读取到纸页 2D Canvas，不复制整套海洋。旋转更新独立于海洋限帧，交互时上限 60 FPS，静止时每秒两次更新共享灯光材质。阅读期间主场景仍为 20 FPS，合书恢复托盘档位。

分页按内容版本与纸页尺寸复用；标记已读、普通翻页和同尺寸重新打开不重新测量整本书，只挂载当前跨页及临时翻页。500 条记录／304 页回归通过，首次排版仍随内容量增长，详见实际测试记录。纸笔声继承声音偏好，不依赖海浪是否加载成功；翻页播放轻纸声，选择日志句子后的自动书写／绘画播放铅笔声。

统一存档键仍为 `tiny-tides-game-v1`，内部版本 10，保留旧外观、海里、见闻与意图；新增 `journalAnnotations`、`journalUiState` 和 `voyageStartedAt`，不保存动画帧。浏览器和 Tauri 依然按来源分别保存。回退基点 `feddc83`，旧代码无法读取版本 10，回退须同时使用升级前的存档备份。历史 HTML 与旧 EXE 保留。

## 整船皮肤 · 当前外观

船只固定为原尺寸的 75%，大小滑杆已移除；旧 `tiny-tides-boat-size-v1` 设置不再读取。切换船型、重启和网页／EXE 都保持此比例，饰品、铭牌、灯位和新尾流同步缩放。开发参数仍在 `boat-model.mjs` 的 `BOAT_SIZE.default`；没有重新开放玩家大小选项。

夜间窗户使用现有玻璃材质的暖色垂直渐变，自发光在 0.80–0.92 间缓慢变化；黄昏渐亮、晨光减弱、白天（含雨天）熄灭。桅灯点光源仍不超过 0.22，不恢复此前船头强亮斑，不添加 Bloom 或额外灯光。

参考图存放于 `history/references/boat-concepts.png`。提供经典款、圆润款、高层款、轻盈款、宽体款、迅捷款、方头款、探索款、温柔款，均免费直接切换，不扣除航行值、不增加新价格。各款同步更换船体、屋顶、船舱、烟囱、护栏及整体造型：不同船宽、弧形/方形船头、单层/双层高度、倾斜前窗和环景驾驶舱。船名、徽章、日志、航行进度不会随换船清空。

`boat-skins.mjs` 集中定义九款参数、配套缩略图和装备保存，`boat-model.mjs` 负责整船模型；仅保留一个航行根节点、一组材质与共用基础几何体。换皮肤时释放被替换的专用船壳/船舱几何体，保留原灯光、铭牌、航迹和见闻引用，不创建额外场景或 WebGL 渲染器。全部造型由本地几何生成，缩略图为轻量 SVG，没有在线模型、字体或 CDN。

版本 5 及更早的存档默认使用经典款；旧颜色归属和颜色值继续存储，仅作历史兼容。没有擅自返还或扣除过去花费的航行值。已有日志、纪念物和徽章均保留。当前存档版本为 10；回退到旧代码前先备份统一存档，旧版不识别新版本。刷新 http://127.0.0.1:4173/ 后打开手账翻到第 3 页即可测试。

## 七个通用安装位置 · 船用装饰

## 航海日志

日志只接收导演的 `encounter_completed`：未实际看见、中断及内部无记录预览不写日志，也不会为了测试伪造玩家历史。现有 10 种见闻均有独立文案，鲸影保持悬念、浮出后接续故事，粉色来客重复相遇轮换文字。解锁的纪念物直接记在页脚，无领取按钮。`quiet_day` 也由导演安排：45–90 分钟活动时间检查一次，最近至少安静 10 分钟、没有在场事件且非暴雨时以 35% 概率记录；每个本地日期最多一次。参数位于 `encounter-catalog.mjs` 的 `QUIET_JOURNAL_PACING`。

日志从第五页开始，实际测量纸页剩余高度，长段落自动分到后页。普通日志可以共享一页，重要见闻支持 large_doodle 或 full_spread；鲸鱼浮出时文字和大幅涂鸦分居双页。只标记已读到结尾的记录，线索在选择或主动合书后标记；阅读中新增记录不强制跳页。开书记住最后阅读位置，蓝纸条到最新篇开头。

最新浏览器回归与性能样本见 `qa/unified-journal.cjs` / `qa/unified-journal-results.json`。旧展示界面测试已被它替代，历史截图和测试结果保留。

## 航行意图 · 第七阶段

线索页末尾有两至三句淡墨候选，Hover／键盘聚焦显示素描批注。点击后原子保存，逐字符书写（30–65ms，标点与换行稍停），笔尖跟随文字，再逐笔绘制 SVG。文字或图画落到后页时自动翻过去。声音使用五段本地合成铅笔样本随机低音量播放，翻页和合书也使用轻纸声，继承静音与隐藏状态。写完留在书中；此前请求关闭则完成后合书。暂不选择可直接合书，不改变意图，以后仍可补写。

支持随海而行、追随深海踪迹、跟随迁徙鸟群、寻找灯光、等待星夜、顺着寒冷海流，以及粉色海豚再次来访后的跟随选择。普通鱼群、普通海豚、安静一天和第一次粉色海豚只记录；鲸影、鲸鱼浮出、迁徙、灯塔、流星、浮冰可提供不同线索句。

`voyage-intents.mjs` 集中配置时长、文案、倾向和回应。每次随机持续 20–45 分钟有效航行，最后两分钟权重缓慢回落；隐藏、暂停和关闭应用时不推进，阅读手账时继续推进，不补算离线时间。仅保留一个意图，新选择替换旧意图；过期或真实事件回应后安静回到自由航行。EncounterDirector 抽选时才读取权重，保留天气、前置、互斥、冷却和安静期，不保证或立即召唤目标。等待星夜只在原本适合极光的环境抽选中增加倾向。

回应日志保存来源意图和日志 ID；追鲸与不追鲸有不同续文。原一对一见闻纪念物规则保留，不增加奖励等级、任务或未实现事件。当前意图在手账档案页以淡铅笔字表示。

手账常驻右下外侧，普通未读用浅蓝灰书签，未完成线索用稍长蓝绿书签。没有未读时收起书签，书本仍保留。

存档版本 9 新增 `voyageIntentState` / `voyageIntentHistory`，条目新增选择、来源与逐条已读字段。版本 1–8 自动迁移，原已读计数转为逐条标记，既有记录不补造事件。回退基点 `4cf111a`；旧版无法读取版本 9，回退需同时使用更新前的存档备份。

## 航海里程 · 原航行值系统

玩家界面显示「≋ 128 海里」，手账首页点击展开便利贴说明，点空白处关闭。正常规则为「1 分钟航行 = 1 海里」；当前整船皮肤免费、纪念装饰随见闻解锁，因此说明不会声称存在已取消的颜色商店。内部 sailingData.points、计时、余额和旧消费记录不变。

正常航行累计 60 秒获得 1 点，不足一分钟的余数保留；新存档从零开始。`main.js` 的 `isSailingActive()` 统一判断有效收益时间：暂停、隐藏、最小化、图形上下文丢失均停止累计；阅读手账时船继续航行，海里仍累计。网页标签隐藏时停止，原生桌宠单纯失焦仍累计。昼夜和天气不影响收益。

`sailing.mjs` 使用真实单调时间差计时，独立于绘制帧率；5 秒卡顿一次结算，超过 30 秒的单次执行间隔丢弃并重置时间基准。墙钟只辅助识别 Windows 休眠，不用于计算收益。当前不支持离线收益，也不保存可用于补算离线收益的时间戳。`sailingConfig()` 集中配置 60 秒兑换、25 秒自动保存、30 秒异常阈值。

`game-save.mjs` 统一管理 `{version:10, shipCustomization, sailingData, ownedColors, colorHintSeen, ownedBadges, seenBadgeNotifications, badgeProgress, encounterHistory, ownedSouvenirs, encounterDirectorState, journalEntries, journalState, journalAnnotations, journalUiState, voyageStartedAt, voyageIntentState, voyageIntentHistory}`；航行字段为 `points`、`accumulatedSeconds`、`totalSailingSeconds`。在周期、整数变化、停止航行、外观修改、合上手账、网页关闭时保存；托盘退出先通知前端保存，最多等待 2 秒后退出。强制结束进程或写入失败仍可能丢失尚未落盘的进度。存档不每帧写入，界面也不每帧更新。

## 自动环境与性能

手动天气按钮已移除。时段按白天 → 黄昏 → 夜晚 → 晨光循环，天气独立沿晴朗 ↔ 阴云 ↔ 小雨 ↔ 暴雨加权随机变化。所有时间为可见且未暂停的世界时间。配置集中于 [environment-config.mjs](environment-config.mjs)：

- 白天/夜晚每段 240–480 秒，黄昏/晨光 90–150 秒；天气持续时间独立随机。
- 过渡 12–25 秒；暴雨只从小雨进入，权重较低，至少间隔 1200 秒；提前 9 秒让海鸥离场。
- 暴雨、夜晚无海鸥。适合的晴朗/阴云夜晚有 45% 概率出现极光，延迟 25–55 秒；星星、月亮、极光和闪电均限于模型附近。
- 水面和极光形变在顶点着色器中完成，保留同一波高公式使船、尾流、海豚和涟漪贴合水面。极光使用正常透明混合，不使用依赖黑底的加法合成。
- 尾流为固定 200 实例的一次批量绘制；雨为固定 1100 线段缓冲。天气变化只改可见性、灯光和材质参数，不重建场景。
- 30 FPS 档像素倍率上限 1.5、像素数上限 921600、最长边 1280；20 FPS 档分别为 1、480000、960。动画按秒推进。
- 无后处理链、无限地面或整屏天空；只保留模型光影和局部环境效果。

## GM 见闻模式

GM 是构建期开关，默认正式构建关闭。开启后，在网页点“编辑预览”，或在桌面托盘进入编辑模式，工具栏会出现 GM 事件选择器；可选择任意一项见闻，或选择“随机见闻”，再点“立即出现”。GM 会立即切换到该见闻适合的时段和天气，结束当前演出并播放所选事件，不受自然冷却、事件链前置或天气条件限制。

GM 工具演出现在正常记录首次发现与重复次数，实际看见且完整结束后生成未读记事本、解锁对应纪念物，并可回应当前航行意图。中途改选、退出或主动中断不生成完成日志。GM 不扣海里，不额外发放航行徽章；记录与正常随机事件共用当前存档。仅内部 `previewEncounter` 仍是无记录演出，供纯视觉测试使用。

```powershell
# 开启 GM 的网页预览
npm run preview:gm

# 开启 GM 的桌面开发窗口
$env:TINY_TIDES_GM='1'
npm run desktop:dev
Remove-Item Env:TINY_TIDES_GM

# 生成保留 GM 的独立 EXE（不重做旧安装包）
```

需要关闭 GM 时，直接使用原有命令重新构建：`npm run preview`、`npm run desktop:dev` 或 `npm run desktop:build`。关闭构建会从最终 HTML 中删除 GM 面板和触发逻辑，不依赖运行时隐藏按钮。


### 手账专项回归

`npm run qa` 后执行 `node qa/unified-journal.cjs`（需要可用 Playwright / Edge），使用隔离浏览器来源，不写玩家预览存档。
原生测试若已有桌宠在运行，可先用 `npm run tauri -- build --no-bundle --config qa/tauri.isolated.conf.json` 构建独立标识测试程序，再运行 `node qa/gm-exe.cjs`；该配置仅用于测试，不作为正式交付。真正交付仍用 `npm run desktop:build:gm`，正常存档标识不变。

手账外观选项以图案显示，悬停可查看名称；正文使用清晰的系统字体。打开时封面绕书脊翻开，阅读状态不显示外侧叠层边框。

翻页：点击右下纸角向后阅读，左下纸角返回；悬停纸角轻抬。支持左右方向键，侧边书签直接前往章节；未加入拖页手势，避免与船模型旋转及纸页滚动冲突。
